# 第三屏交互改为「参考视频」的那种：标题吸顶 + 卡片逐列填充

之前用的是「整段钉住 320vh」，参考错了。视频里那段其实**不钉整屏**，而是正常文档流滚动，标题吸顶，卡片和大数字随滚动一列一列填进来。

## 视频里的实际交互

1. 标题（图标 + 两行 slogan + 下面的细线）先进入，然后 **sticky 吸在顶部**，在整段滚动过程中一直停在导航下方。
2. 卡片行是 3 列的一整行，初始为空；随着滚动 **从左到右一列一列出现**（第 1 列 → 第 2 列 → 第 3 列），每列淡入 + 轻微上移。
3. 每一列的**大数字**（5x / No / Zero 对应我们的 +85% / 13k / +90%）在该列卡片出现之后、稍微延迟地出现在同一列下方，所以视觉上是「一整列一整列地长出来」。
4. 已出现的列保持可见；向上回滚逐列反向消失，完全可逆。
5. 段落结束后标题解除吸顶，页面继续正常向下滚动。

## 具体改动（MetricsSection）

- 去掉 `height: 320vh` 的钉住轨道和内层 `position: sticky; height: 100dvh` 的整屏容器，改为按内容高度的普通区块（约 140–160vh 的滚动跨度，靠内容 + 底部留白自然形成）。
- 标题块（含渐变细线）包在 `position: sticky; top: 69px` 的容器里，随段落滚动吸顶，段落结束时随父容器一起滚出。
- 进度计算保持现有 rAF + `getBoundingClientRect` 写法，但映射到 **3 个列**而不是 8 个块：
  - 列 i 的卡片：`smoothstep(i*0.22, i*0.22+0.26, p)`
  - 列 i 的数字：同曲线延后 0.10（数字跟在卡片后面）
  - 标题与细线在 p≈0 就已可见（进入即显示，和视频一致）
- 每列动画：opacity 0→1 + translateY 24px→0，520ms `cubic-bezier(0.22,1,0.36,1)`，与现有一致。
- `prefers-reduced-motion` 时直接全部显示。

## 保持不变

- Figma 的 UI 参数全部不动：`#FAFAFA` 背景、Clash Display 48/56 标题、460px 三色渐变细线、3×(400×540) 描边卡片、`#D9D9D9` 图片占位、Montserrat 文案层级、100px/68px 大数字 + 18px 标签。
- 导航栏与底部输入框的浅/深色联动逻辑不动。
- 第一屏、第二屏的动效与滚动逻辑完全不动。

## 验证

Playwright 在 1280×900 与 1440×900 下分档滚动第三屏，抓取「空 → 第一列 → 第二列 → 第三列」四个阶段截图，确认标题吸顶、列按序填充、回滚可逆，且段落结束后页面正常继续滚动。
