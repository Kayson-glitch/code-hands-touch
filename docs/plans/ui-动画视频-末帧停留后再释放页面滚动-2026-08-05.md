# UI 动画视频：末帧停留后再释放页面滚动

## 目标
让「UI 动画视频」（Halftone 手部滚动动画）在滚到最后一帧后，继续在末帧停留「几帧」的滚动距离，然后再把滚动权交还给页面正常滚动。

## 当前行为
- 页面位于首屏、scrollY = 0 时，鼠标滚轮被组件拦截。
- 滚轮驱动 `progressRef` 从 0 → 1，对应 49 帧从第 1 帧播放到最后一帧。
- `progressRef` 到达 1 后，滚轮事件不再被 `consume()`，页面开始正常滚动。

## 计划修改
只改动 `src/components/HalftoneHandsFooter.tsx` 的滚轮劫持逻辑，其余渲染、流体、呼吸、视差全部不动。

```text
滚动阶段划分：

  阶段 A: 手部帧播放
  progress 0 → 1   (49 帧)

  阶段 B: 末帧停留
  holdProgress 0 → 1   等价于额外滚动 HOLD_FRAMES 帧
  画面锁定在最后一帧

  阶段 C: 释放页面滚动
  滚轮不再被拦截，页面正常向下滚动
```

### 具体实现
1. 新增常量 `HOLD_FRAMES = 4`（默认停留 4 帧，可调整）。
2. 新增 `holdProgressRef = { target: 0, v: 0 }` 用于记录阶段 B 的消耗进度。
3. 改写 `consume(rawDy)`：
   - 向下滚动时，先判断阶段 A 是否完成；若未完成则继续推进帧播放。
   - 阶段 A 完成后，进入阶段 B，累积 `holdProgress.target`，并继续 `preventDefault()`。
   - 阶段 B 完成后，返回 `false`，滚轮交还页面。
4. 向上滚动时保持可逆：
   - 若页面已在顶部且阶段 B 有剩余，先回退 `holdProgress`。
   - 阶段 B 回退到 0 后，再回退阶段 A 的帧播放。
5. 阶段 B 期间，渲染仍使用最后一帧（`FRAME_COUNT - 1`），流体 hover、呼吸、视差照常运行。

## 验证方式
用 Playwright 模拟向下滚轮：
- 确认 `window.scrollY` 在手部帧播放 + 停留阶段期间保持 0。
- 确认停留阶段结束后 `window.scrollY` 开始增加。
- 确认向上滚动可逆。

## 需要确认
停留「几帧」默认按 4 帧处理（即总锁定滚动距离 ≈ 53 帧）。如需改为其他数值（如 2 帧、6 帧），请在批准前告知。
