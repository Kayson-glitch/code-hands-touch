# 第三屏交互：1:1 复刻 kore.ai 的「列传送带」

我把参考站点那一段的真实实现读出来了（`#enterprise-ai-outcomes` / `.k2-cards-*`），并逐帧采样了它的计算样式。当前我们的实现（三列淡入 + 上移 24px）机制完全不同，需要重写交互层。

## 参考站点的真实机制（实测数据）

- 整段被钉住：`.k2-cards-sticky { position: sticky; top: 导航高度 }`，段落总高提供滚动行程，进度写成 CSS 变量 `--p`（0→1）。进度到 1 后段落自然解除钉住继续滚动。
- 卡片区 `.k2-cards` 是一个 **固定高度 + overflow:hidden 的窗口**（实测 `--h ≈ 856px`，等于「一列」的完整高度）。
- 每一列 `.k2-card-item` 是「上：图文卡片 / 下：大数字」的整体，**在这个窗口里整体向上平移**：
  - 起点 `translateY(+313px)`（完全在窗口下方，被裁掉，opacity 0）
  - 终点 `translateY(-345px)`（卡片上半部被裁出窗口顶部，大数字停在窗口中）
  - 所以视觉上是「卡片从下方升起 → 穿过窗口 → 卡片被顶出、只剩大数字停住」，不是淡入。
- 每列进度：`t_i = clamp(p * 3 - i, 0, 1)`（实测 p=0.311 时 t0=0.934、t1=t2=0；p=0.546 时 t0=1、t1=0.639；p=0.781 时 t2=0.344 —— 完全线性、无缓动、三等分错峰）。
- 透明度是二值：`t > 0 ? 1 : 0`（不做渐显）。
- 完全可逆，向上回滚逐列退回窗口下方。

## 我们要改的内容

只重写 `src/components/MetricsSection.tsx` 的交互层，UI 参数（Figma 的标题、渐变细线、400×540 卡片、100px 大数字、Montserrat 文字）保持现在的值不变。

- 结构改为：
  ```text
  section（高度 = 钉住行程，约 300vh）
    └ sticky(top: 69px, height: 100dvh)
        ├ 标题 + 渐变细线（始终可见）
        └ 窗口 div（height = 一列完整高度, overflow: hidden）
            └ grid 3 列，每列 = [卡片] + gap + [大数字+标签]
  ```
- 用 rAF + `getBoundingClientRect` 算出段落进度 `p`（沿用现有写法），每列取 `t = clamp(p*3 - i, 0, 1)`，线性无缓动。
- 每列 `transform: translate3d(0, lerp(start, end, t))`，`opacity: t > 0 ? 1 : 0`；start = 窗口高度（在窗口下方），end = -(卡片高 + gap)，两者按实际测量高度计算，不写死像素。
- 不加 transition（位移由进度直接驱动，否则会和滚动打架）；`prefers-reduced-motion` 时直接让所有列停在终点。
- 窗口高度取「卡片高 + gap + 数字块高」，用 ref 量出真实高度写进 CSS 变量，保证不同视口都不错位。
- 段落进度到 1 后钉住自然结束，页面继续向下滚动；主题仍按现有 `data-dark-section` 逻辑保持浅色。

## 技术说明

- 行程长度：`height: calc(100dvh + 3 * 90vh)` 量级，保证每列约 90vh 的滚动才走完，节奏接近参考站（可在实现后按截图微调）。
- 顶部 sticky 偏移沿用导航高度 69px，标题块加 `#FAFAFA` 底色避免列穿透。
- 底部为固定的 Fin 输入框预留安全距离，窗口高度受 `100dvh - 顶部标题块 - 底部安全区` 限制，超出时整列等比缩放（用 clamp 字号，不裁内容）。

## 验证

Playwright 在 1280×900 与 1440×900 下按段落进度 0 / 0.15 / 0.3 / 0.45 / 0.6 / 0.8 / 1 抓图，逐列对照参考站的同一状态：第一列卡片升起→顶出只剩数字、第二列正在穿过、第三列尚未进入，回滚可逆，结束后页面正常继续滚动。
